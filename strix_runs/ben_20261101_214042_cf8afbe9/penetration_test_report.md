# Security Penetration Test Report

**Generated:** 2026-11-01 13:46:22 UTC

# Executive Summary

对 **117.72.199.2:3000**（OWASP Juice Shop v20.2.0，Express + Sequelize/SQLite + Angular SPA 的电商演练站）完成外部黑盒测试。该站在**无任何凭据**的情况下被完整击穿登录与权限边界，风险等级：**严重**。

**总体风险态势：** 极高。认证与授权边界整体失效，攻击者无需注册即可取得管理员会话并读取全量用户数据。

**关键发现**
- **登录接口 SQL 注入**：邮箱填 `admin@juice-sh.op'--` 即返回管理员 JWT，密码字段被忽略；凭该会话读取 39 个用户对象。
- **JWT 校验不锁算法**：`alg:none` 空签名令牌被接受，可伪造任意身份；RSA 公钥可匿名下载，RS256→HS256 混淆成立；token 载荷内嵌管理员口令哈希 `0192023a7bbd73250516f069df18b500`（即 md5(admin123)）。
- **文件服务未鉴权**：`/ftp/` 暴露目录列表，可匿名下载 KeePass 密码库（3246 字节，真实 kdbx 魔数）与标注 confidential 的内部并购计划正文。
- **运维日志未鉴权**：`/support/logs/access.log.2026-11-01` 匿名可读 50528 字节 / 391 行，含可重放的完整会话 JWT、账号邮箱、订单号与 10 个客户端真实 IP。
- **搜索接口 SQL 注入**：注释符绕过 `deletedAt IS NULL`，拉出软删除全表 57 行。
- **密保接口可枚举**：按邮箱稳定判定账号存在性并取得密保问题题干。

**业务影响**
用户身份数据（邮箱、角色、会员凭据 deluxeToken、登录 IP）可批量获取；管理员后台操作权限（商品、价格、用户、订单）实际处于开放状态；内部密码库与并购机密外泄；日志中的会话令牌使账户接管可复现，且绝对路径与日志哈希暴露使审计痕迹可被规避。若该实例承载真实业务数据，需按数据泄露事件处置。

**修复主线：** 认证层（参数化查询、JWT 算法白名单、密钥与公钥下线）为第一优先，其后是静态文件与运维路径的鉴权收口，最后补输入层与接口级限频。

# Methodology

依据 **OWASP WSTG** 与 **PTES** 开展外部黑盒（black-box）测试，全程以真实 HTTP 请求响应为唯一证据来源，所有结论均可由记录在案的请求复现。

**测试类型：** 未认证外部黑盒。
**范围：** `http://117.72.199.2:3000` 单一目标，含商城前台 REST API（`/rest`、`/api`）、静态文件服务（`/ftp`）、运维支持路径（`/support/logs`）、指标与配置端点（`/metrics`、`/rest/admin`）。
**约束：** 以只读与最小必要请求为原则；未执行删除、批量爆破、拒绝服务或任何影响可用性的动作；未访问授权范围外地址。

**开展的测试类别：**
1. 侦察与攻击面测绘：根路径基线、响应头、SPA 资源与 REST 路由枚举、目录列表发现。
2. 认证测试：登录接口 SQL 注入、JWT 结构解析、算法白名单缺失验证（alg=none、RS256→HS256 混淆）、签名与载荷篡改对照组。
3. 授权测试：未认证访问用户集合、用户详情、身份查询接口；对象级越权尝试与结果判定。
4. 注入测试：登录参数与商品搜索参数的 SQL 注入，含基线/单引号/无引号闭合三组差分与软删除行验证。
5. 信息泄露测试：静态文件目录、运维日志、审计清单、应用配置、版本与 Prometheus 指标。
6. 反证与排除：对 SPA 兜底响应、静态 index 兜底、401 受控端点、无差分端点逐项排除，避免假阳性。

# Technical Analysis

共确认 **6 个可复现漏洞**（严重 2、高危 2、中危 2），全部以真实请求响应取证。

**严重**
1. **登录接口 SQL 注入导致管理员接管**（`POST /rest/user/login`）— 邮箱 `admin@juice-sh.op'--` 与 `' OR 1=1--` 均返回 200 与管理员 JWT（`role=admin`、`id=1`），密码字段不参与校验；凭该 token 访问 `/api/Users` 返回 200 / 39 个用户对象。
2. **JWT 算法未锁定导致任意身份伪造**（`/api/Users`、`/rest/user/whoami`）— `alg:none` 空签名令牌被接受；伪造 `id=5 / ciso / deluxe` 被服务端采信并带出 deluxeToken；匿名可读 `/encryptionkeys/jwt.pub`（248 字节）使 HS256 混淆成立；token 载荷含 `password=0192023a7bbd73250516f069df18b500`。对照组（无头、乱码、错签、篡改载荷、空 Bearer）全部 401，证明缺陷是算法白名单缺失而非缺少校验。

**高危**
3. **文件服务未鉴权**（`/ftp/`）— 目录列表 12419 字节；`acquisitions.md` 909 字节含 confidential 内部并购正文；`incident-support.kdbx` 3246 字节、文件头 `03d9a29a67fb4bb5`、两次下载 md5 一致；`order_*.pdf` 1826 字节 `%PDF-1.3`。
4. **运维日志未鉴权**（`/support/logs/`）— `access.log.2026-11-01` 50528 字节 / 391 行，含 URL 中的完整 JWT、账号邮箱、订单号、10 个客户端 IP 与 UA；`audit.json` 521 字节泄露绝对路径 `/juice-shop/logs/` 与日志 md5 哈希。

**中危**
5. **商品搜索 SQL 注入**（`/rest/products/search?q=`）— `%27%29%29--` 返回 21791 字节 57 行，含 10 条 `deletedAt` 非空的软删除记录；基线 `q=apple` 921 字节 3 行、`q='` 30 字节 0 行。
6. **密保问题接口用户枚举**（`/rest/user/security-question?email=`）— 存在账号返回 134/146 字节含问题原文，不存在返回 2 字节 `{}`，差分稳定。

**系统性根因**：三处缺陷共享同一模式——**信任了客户端可控的结构化输入**（SQL 字符串拼接、JWT header 算法自述、URL 中的对象标识），且鉴权在路由层按"前缀"而非"能力"划分，导致带 `admin`、`support`、`ftp` 前缀的路径被默认视为内部面。防御被实现为分散的单点检查，缺少统一的输入校验与默认拒绝策略；日志与静态目录直接暴露在 Web 根下，使已经发生的测试流量本身成为二次泄露源。

**已排除（附控制点）**：`/snippets`、`/api-docs/swagger.json` 为 Angular/静态 index 兜底（与根字节数一致、含 `app-root`）；`/support/logs/error.log` 404；`/b2b/v2/orders` 匿名 401（全局 JWT 中间件）；`/rest/track-order/` 对伪造与真实 UUID 返回同构 76 字节、仅回显输入，无存在性差分；`/rest/basket/{id}`、`/api/Users/1`、`/api/Feedbacks/1` 无 Authorization 时统一 401 / 972 字节。

**未验证项（缺口已注明）**：购物车对象级越权需真实登录会话方可持续对照，本轮自造令牌在该端点返回 401；搜索注入的 UNION 取数能力未展开；`/rest/basket` 写操作路径受只读纪律未测。上述均为未验证，不作为已排除处理。

# Recommendations

**立即处置（48 小时内）**
1. 登录接口改为参数化查询/ORM 绑定变量，禁止拼接 email；邮箱加格式白名单；登录失败统一响应。
2. JWT 校验显式锁定 `algorithms: ['RS256']`，拒绝 `none` 与 HS*；下线 `/encryptionkeys/` 目录的匿名访问；从 token 载荷移除 `password` 等敏感字段，增加 `exp`、`jti` 与吊销名单。
3. 全量重签密钥并作废现有 token——现有密钥、口令哈希与会员 deluxeToken 均已外泄，仅修补校验逻辑不足以清除已有会话。
4. 关闭 `/ftp` 目录列表与静态直出，将 KeePass 库、备份文件、内部文档移出 Web 根目录；`/support` 整组路径加管理员鉴权或从公网入口摘除。
5. 日志停止记录 URL query 中的 token，写盘前对 email、订单号、IP 脱敏；审计清单不对 Web 暴露。

**短期（2 周内）**
6. 搜索接口改用绑定参数与 `Op.like` 构造器，软删除条件收敛到模型默认 scope；对 q 做长度与字符白名单。
7. 密保查询移入重置流程内部，须先校验重置令牌；对不存在邮箱返回等长统一响应；对该接口与登录接口按 IP + 账号双维度限频并加图形验证。
8. `/rest/admin/application-configuration`、`/metrics`、`/rest/admin/application-version` 加鉴权，仅对运维网段开放；OAuth clientId 按最小暴露原则收敛。
9. 为全部 `/api/*` 与 `/rest/*` 补对象级授权：以会话主体 id 过滤集合查询，禁止由 URL 指定归属对象。

**中期**
10. 建立路由级默认拒绝策略：带内部语义前缀的路径（admin、support、ftp、metrics）统一经鉴权中间件与网络 ACL 双重约束。
11. 引入 CI 阶段的 SAST/DAST 与依赖扫描，把 SQL 拼接、JWT 配置错误列为阻断项；对日志与静态目录做部署前暴露面检查。

**复测与验证**：修复后以本轮六条 PoC 作为回归用例——`alg:none` 与 HS256 混淆须返回 401；`admin@juice-sh.op'--` 登录须返回 401；`/ftp/`、`/support/logs/` 须返回 401/404；`q=%27%29%29--` 结果行数须与 `q=apple` 同构且不含 `deletedAt` 非空记录；`security-question` 对存在/不存在邮箱须返回等长响应。建议复测同时核查历史日志中已泄露令牌对应的账号是否被异常使用。

# 2026-11-01 BenProject 迁移到 openai-agents SDK

## 完成内容

按照 strix 项目的架构规范，将 BenProject 从手写多轮 Agent 循环迁移到 openai-agents SDK：

### 1. requirements.txt
- 新增 `openai-agents[litellm]>=0.19.0,<0.20`, `pydantic>=2.11.3`, `pydantic-settings>=2.13.0`, `litellm>=1.101.0`
- 保留原有的 docker, mcp, Jinja2, PyYAML 等依赖

### 2. Ben/config/settings.py — pydantic-settings 化
- `LlmSettings(BaseSettings)`: model/api_key/base_url/timeout/max_turns，支持 strix 风格别名（DEEPSEEK_API_KEY / LLM_API_KEY / OPENAI_API_KEY 等）
- `Settings(BaseSettings)`: 组合 LlmSettings + Docker 执行器配置 + 授权目标白名单
- `allowed_targets` 用 str 字段存储（避免 pydantic-settings JSON 解析问题），通过 @property 转为 tuple
- 新增 `configure_sdk_model_defaults()`: 设置 SDK 的 API Key、Base URL、`chat_completions` API 路由、禁用遥测
- 兼容属性：deepseek_model / deepseek_api_key / max_agent_turns 等保持旧代码可访问

### 3. Ben/tools/function_tools/ — @function_tool 工具
- 新建 `http_check.py`: `@function_tool(strict_mode=False)` 装饰，从 ctx.context 取 executor/allowed_targets
- 新建 `load_skill.py`: 知识片段加载工具
- 新建 `mcp_tools.py`: list_mcps + call_mcp 工具
- 工具上下文通过 `ctx.context` dict 注入（executor, allowed_targets, command_timeout）
- 旧的 ToolSpec/ToolRegistry 保留（未删除），但新架构不再使用

### 4. Ben/agents/factory.py — SandboxAgent 构建
- `build_agent()` 返回 `SandboxAgent`，挂载 4 个 @function_tool 工具 + Filesystem/Shell capabilities
- model=None，推迟到 RunConfig 解析
- `_BASE_TOOLS = (http_check, load_skill, list_mcps, call_mcp)`

### 5. Ben/core/runner.py — SDK Runner 驱动
- `AgentRunner` 使用 `Runner.run_streamed()` + `RunConfig` 替代手写循环
- 异步 `run_async()` 方法：配置 SDK -> 构建 agent -> RunConfig -> Runner.run_streamed -> 流式收集 events
- 从 run items 提取工具调用记录（ToolCallItem/ToolCallOutputItem）和最终文本（MessageOutputItem）
- 保留报告/轨迹持久化（report.md + trace.json）
- 不再依赖 DeepSeekClient / ToolRegistry / ToolRuntime

### 6. Ben/interface/main.py — 入口重写
- Windows asyncio 事件循环策略设置
- `_selftest_llm()` 改用 SDK Runner 做连通测试
- `_run_task()` 使用新的 AgentRunner（只需 settings + executor）
- 保留 --selftest-docker / --selftest-llm / --selftest-tools / --keep-container 参数

### 关键技术决策
- `strict_mode=False` 用于有 dict[str, str] 参数的工具（对齐 strix 的 mcp/reporting 工具）
- `set_default_openai_api("chat_completions")` — DeepSeek/GLM 端点不支持 responses API
- RunConfig 不使用 SDK 内置 sandbox（工具的 Docker 执行由工具自身管理）
- 旧的 `Ben/llm/deepseek_client.py` 和 `Ben/tools/registry.py` 保留但不再被新架构引用

## 修复：plain Agent + MaxTurnsExceeded + 工具输出提取

### 问题：SandboxAgent hosted tools 与 chat_completions 不兼容
- SandboxAgent 的 Filesystem/Shell capabilities 注册 hosted tools（apply_patch/view_image/exec_command）
- chat_completions API 不支持 hosted tools → 报错 `Hosted tools are not supported with the ChatCompletions API`
- **修复**：factory.py 改用普通 `Agent`（无 capabilities），http_check 通过 ctx.context 中的 sandbox_session 直接 exec 命令

### 问题：SandboxRunConfig 与 plain Agent 不匹配
- runner.py 原先在 RunConfig 中传 `sandbox=SandboxRunConfig(...)`，plain Agent 不需要
- **修复**：从 RunConfig 移除 sandbox 参数，保留 DockerSandboxClient/SandboxSession 生命周期管理（创建→ctx.context 注入→关闭）

### 问题：MaxTurnsExceeded 异常导致工具调用记录丢失
- SDK 在达到 max_turns 时从 `stream.stream_events()` 抛出 `MaxTurnsExceeded` 异常
- 异常被 `except Exception` 捕获，但 `stream.new_items` 中的 items 未被提取
- **修复**：在 stream_events 循环内单独 catch `MaxTurnsExceeded`，然后从 `stream.new_items` 提取 items

### 问题：ToolCallOutputItem.raw_item 是 dict 而非对象
- chat_completions 模式下，ToolCallOutputItem.raw_item 是 `dict`（含 call_id/output/type 键）
- 原提取逻辑用 `getattr(raw, "output", None)` 对 dict 无效
- **修复**：`_extract_tool_invocations` 改为同时支持 dict 和对象格式，按 call_id 匹配 call→output

### 问题：Turn 计数不准
- SDK 不通过 stream_events 发送 turn 事件
- **修复**：通过检测 ToolCallItem 的批次（上一个 item 不是 ToolCallItem 时 = 新轮次）来计数

### 最终测试结果（4轮扫描 http://117.72.199.2:3000/）
- 4 轮，16 次 http_check 工具调用，39 条 items，耗时 ~32s
- 模型探测了根路径、robots.txt、manifest.json、/api 路由（500）、/api/users（401）、/api/admin/users 等
- 工具输出正确提取：状态码、响应头、缺失安全头（CSP/HSTS/Referrer-Policy/Permissions-Policy）
- 报告文件（model 中间分析文本）+ 轨迹文件（完整工具调用 JSON）均正常保存

## 编排逻辑对比：Ben vs sapper-v2

- Ben：常驻 root（openai-agents SDK 单循环）+ asyncio 子 agent。派活单位是 agent，`create_agent(name, task, skills, inherit_context)`；root 纯编排（system_prompt.jinja `<root_agent_directive>`，README §八 明确"编排发生在提示词里，不是代码里"）。计划只在 root 上下文 + todos.json / notes.json / coverage / threat_model 落盘，没有任务 DAG。子 agent 长驻多轮、可再派生孙 agent（BEN_MAX_SUBAGENTS 上限）、agent_finish 回父收件箱、send_message_to_agent 双向通信。
- sapper：无常驻 agent。每一步都是 `claude -p` 一次性调用（reason / explore / verify），角色由 templates/*.md 决定。计划 = `.sapper/` 里的 facts（节点，不可变，kind+data）与 intents（边，from→to）。指挥官不是"记住计划"，而是每轮重读全图再提 ≤3 条 intent；可执行性由代码 `is_ready/frontier` 结构性判定（from 事实都在 + 未确认 + 未认领）。`auto` 循环 reason→explore→(verify)→图签名变化检查；上层还有 command.md（多 challenge 板面 work/hire/fire 分配）、sweep（轮转）、blindspot/brainstorm（发散模式）。
- 关键差异：派活单位 agent vs intent；状态在上下文 vs 在磁盘；并行靠消息 vs 靠 claim + flock；结果信任靠 root 汇总 vs 独立 verify 角色 + 不可变事实。

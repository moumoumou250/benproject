## 先识别，再绕过

在动手绕之前，先知道挡你的是什么，以及挡在哪一层：

- `wafw00f <target>` 指纹产品；`nmap --script=http-waf-detect -p443 <host>` 作补充。
- 或者直接打一发无害探针，看返回：厂商拦截页、裸 403/406、连接被重置、超时。
  记下命中的规则族（SQL 关键字 / XSS 标签 / 路径规则 / 频率限制），后面绕的是它。

频率限制和规则拦截是两回事。被限流时绕过技巧没用，该降并发；被规则拦时才换位置和编码。

## 绕过顺序：先位置，后编码

**位置优先**——同一个 payload 换位置经常一次就过，编码绕过则要试很多次：

1. query 参数 → 2. JSON body 字段 → 3. 自定义/常见头 → 4. 路径段 → 5. multipart 字段

**然后才编码**

- 双重 URL 编码；`%0a` / `%0d` 换行插在关键字中间
- 大小写混用、内联注释分割（`un/**/ion`、`sel//ect`）
- 空白变形（`+`、`%09`、`%0c`）、同义函数与等价语法
- HTTP 参数污染：同名参数给两次，看后端取第一个还是最后一个
- `Content-Type` 改写（表单 / JSON / multipart 互转常常过不同规则集）

**按栈选探针**，不是每一种都试 SQL：JSON/Mongo 打操作符（`$ne`/`$gt`）、搜索框打
ES DSL 或 `OR`+`total` 差分、Java 打 HQL/SpEL、有模板打 SSTI。

## 配额

每个被拦参数 2～3 个变体就够。还没过就记录「被 WAF 拦截（规则族）」，
**换一个没被拦的参数继续**，而不是在这个参数上磨到出数。

- 禁止把"每个 path 丢一个 `'`"当成 WAF 探测或进度。
- 拦截不等于没有漏洞。写清被拦的参、试过的变体、以及为什么停下——这是 N/A 的正确形态，
  不是证伪成功。

## 本沙箱不做的部分

下面这些在别人的 WAF 手册里很常见，但在这里**不做**，做了也是无效动作：

- 找源站 IP 直连绕过（Shodan / 历史 DNS / 邮件头）——目标是白名单内主机，直连源站属于范围外；
- 原始分块 / HTTP2 帧级走私——需要 raw socket 权限，沙箱没有；
- 大规模并发打规则——授权闸门只放行只读方法，且这属于可用性风险。

被拦时如实写「WAF 拦截，未取得差分」，把精力转到没被拦的面。

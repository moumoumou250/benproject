## 差分面判别

先判断这个口有没有差分面，再决定要不要发探针。**差分面 = 回包结构里存在你可以观察变化的东西**，
不是"接口返回了 200"。

| 回包长什么样 | 算不算差分面 | 怎么做 |
|--------------|--------------|--------|
| 有 list / total / 业务字段，哪怕 `total=0`、数组是空的 | **有** | 换参、换 id、注入都要测。空列表只说明条数是 0，不说明没鉴权 |
| 报错、500、超时，或长度/耗时和基线明显不同 | **有** | 先对照一两次确认稳定，再按类型选探针 |
| 缺个参数却吐出名单/详情 | **有（未授权例外）** | 这本身就是线索，顺着打 |
| 通篇只有一句"请登录 / NotLogin"，没有 list、没有 total、没有业务字段 | **无** | 整段 N/A + 原因，不要挨个丢 `'` |
| 只有公开静态页、跳转官网、欢迎页 | **无** | 记 N/A，转其它入口 |

**空列表不等于登录墙。** `{"code":0,"data":{"total":0,"list":[]}}` 是出了结构、条数是 0；
整页只有一句登录失败码才是登录墙。把前者误判成后者，会把整站当成打不动。

## 登录闸收敛（同闸停）

同一批业务口全部返回**同一家族回码**（请重新登录 / NotLogin / 系统繁忙 / 升级改造中），
同时满足下面全部条件时，这一组要停，而不是继续开矩阵：

1. 业务 path 已经从 JS / 网关 / 抓包里抽出来；
2. 未登录例外（公开枚举、静态 JSON、缺参仍出业务字段）已经点过；
3. 其余业务口是同一家族回码，没有条数、时间、长度的差分；
4. 没有出现未授权能读到的他人主体数据。

**然后停这一组**，把类型矩阵在**有差分面**的那几个口上跑完，记 done 换下一个面。
不要对着"请登录"三个字灌注入——那不是深挖，是空转。

**重新开的三个信号**（只有这三个才值得回来）：

- 回码变了（不再是那一句登录码）；
- 抽到新 path（新版本 chunk、新网关）；
- 出现新的业务 host（同品牌 api / admin / gateway）。

同产品下一个 host 还是同一套 `baseURL` + 同一回码 → 一眼差分即可，不另开全矩阵。

## 什么时候停

- **不稳定就停**：偶发 500/超时对照一两次；差不稳就记录并换面，不要重试到"通"。
- **没有差分就停**：换参打过仍无条数/内容/时间差 → 证伪，写 N/A + 原因。
- **禁止向差分前进**：反复加重 payload 直到出数，是把误报和真实影响混在一起。
  探针按栈选（JSON 打操作符、搜索框打 ES/OR+total、Java 打 HQL/SpEL、模板打 SSTI、
  SQL 面走 `'`/布尔/延时），不是把每个 path 都用单引号过一遍。

## 差分是唯一硬证据

结论必须能写成对照：**基线是什么、探针后变成什么、差在哪个字段**。
只有状态码或只有"接口 200 有 JSON"不算证据（暗含：公开运营数据、本账号权限内的数据也不算）。
拿不准归入"未验证"而不是升级为漏洞——收口规则见 `analysis/counterevidence`，不在此重复。

## 沙箱内怎么取基线

`repeat_request` 基于已捕获请求改单个字段重放，适合做基线/探针成对对照，不必重拼 curl。
没有代理留痕时用 `exec_command` 直接取证。注意当前授权闸门只放行只读方法，
写类差分（改状态、改对象）取不到就是取不到——如实记 N/A，不要用别的路径绕。
